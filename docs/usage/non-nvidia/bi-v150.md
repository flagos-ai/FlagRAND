# FlagRAND 天数智芯 BI-V150 运行指南

## 验证环境

统一 CI 后端名为 `iluvatar`。`./setup.sh iluvatar` 优先复用当前 Python 中与 SDK 匹配的天数 Torch、Triton 或 FlagTree，在项目的 `.venv` 中安装 FlagRAND 和测试依赖。已有 CoreX 4.4 的 Python 3.10 镜像可以直接使用。`FLAGRAND_SYSTEM_PYTHON=/flagos/bin/python3` 可指定已有环境的解释器。

从空环境安装时，脚本创建 Python 3.12 虚拟环境，按厂商编译器报告的 SDK 版本选择天数源上的 Linux x86-64 wheels。CoreX 4.4.0 用 `torch==2.7.1+corex.4.4.0` 和 `triton==3.1.0+corex.4.4.0`，CoreX 4.5.0.20260804 用 `torch==2.10.0+corex.4.5.0.20260804` 和 `triton==3.2.0+corex.4.5.0.20260804`。后续新 SDK 的镜像可通过其自带 Python 安装。单独安装到已激活的测试环境可运行：

```bash
uv pip install --python "$(command -v python3)" -e '.[test,iluvatar]'
```

## 原生参考

CoreX 4.4 的 MRG32K3A 和四种生成器的 Poisson 沿用仓库的修正参考，其余接口调用
SDK 的 host RNG。CoreX 4.5 将公开头文件转发到 `IX/`。在这套 SDK 上，基准通过
`libcurand.so` 的 `curandCreateGenerator` 在 GPU 上生成数据，使用该版本自己的种子初始化和分布实现。
两版的 MRG32K3A 在相同种子下也可产生不同初始状态，复现实验时请同时记录 SDK
版本和基准结果中的参考实现名称。SDK 安装在自定义目录时，可通过 `COREX_HOME` 指向该目录。

## 当前验证范围

CoreX 4.4.0 已在 BI-V150 上完成镜像环境安装和 20 项原生参考验证。测试环境使用
Python 3.10.18、Torch `2.7.1+corex.4.4.0` 和 Triton `3.1.0+corex.4.4.0`。
完整安装记录对应适配过程中的安装脚本快照。后续新增的 SDK 切换逻辑已完成隔离环境验证，
当前安装脚本的完整真机复测待完成。

**CoreX 4.5.0.20260804 的 BI-V150 GPU 精度与性能待验证。** 公开 SDK 已完成
MRG32K3A 设备探针的 `ivcore11` 交叉编译，以及厂商 Python wheel 的版本和依赖解析。
当前可用机器的内核驱动为 4.4.0，加载 4.5 运行时得到驱动版本不足或驱动不匹配错误。
4.5 的设备执行需要匹配的驱动环境。

## 用 optest 的参数运行单个算子

在已安装测试依赖的 BI-V150 环境中，从仓库根目录运行。例如，以下命令分别记录
MRG32K3A 单精度均匀分布的精度和性能结果。

```bash
export FLAGOS_GPU_VENDOR=iluvatar
python -m pytest tests -m mrg32k3a_uniform_f32 --ref cpu --quick --record json --output accuracy.json
python -m pytest benchmark -m mrg32k3a_uniform_f32 --level core --record json --output performance.json
```

性能结果包含每个形状的 FlagRAND 延迟和同卡原生参考延迟，单位为毫秒。如需和已有的
optest 外部基线比对，可在第二条命令中追加 `--base-data /path/to/ops-baseline.json`。

上述 pytest 参数和 JSON 格式已通过 CoreX 4.4 真机及 optest 解析器验证。中央
`flagos-optest` 在提交 `a36c154` 的库识别名单中尚未登记 FlagRAND，完整中央调度仍待接入。
