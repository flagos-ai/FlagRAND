# 第三节 实现方法

Philox 保持计数器递推及既有 API 语义；XORWOW 复用原有状态递推实现；MRG32K3A 使用两组三阶模递推；MTGP32 在 FlagTree 3.6 路径中通过共享内存复用协同更新状态。MTGP32 的未消费 raw word 用于后续调用。N≤65536 的 raw32 包括 fresh aligned 调用，复用已有有界 raw 窗口，命中时用当前 stream 的 D2D 复制，refill 写输出的路径保留。此路径不增加派生数组，短调用 raw 预取窗口约 4 MiB，单独计入存储。FP32/FP64 uniform、normal/lognormal 与 Poisson 在 N≤65536 时使用有界派生缓存。uniform FP64 和 Poisson 按读取起点的奇偶位置分别保存；Poisson 仅保留最近一个表身份。normal/lognormal 四个 API 共用一个最近的 _normal_cache 条目，以 raw 窗口、mode、dtype、参数位模式与 raw 起点余数识别；条件变化时替换，新增单个数组上界约 4 MiB。混合调用的活跃派生张量上界为 20×(1048576+255)=20976620 字节，约 20 MiB，不含 raw 窗口、已有 alias 表及尚未完成的 stream 工作暂时保留的旧存储；大 raw 窗口不建立派生缓存。当前 stream 上通过 mcMemcpyAsync 执行 D2D 复制；缓存替换、耗尽及 seed 重置释放派生引用，保留 offset、切分调用和 stream 生命周期语义。Poisson 为四生成器提供分布转换，表构造与完整 API 的计时范围以本轮 manifest 为准。

共享状态复用和两阶段变换的收益由设备 kernel 时间对照说明。短调用缓存减少重复变换提交、视图构造与复制分发，同时执行 D2D 复制。完整 API 时间与 kernel、memcpy 活动分别报告，不将主机路径的收益归为单个 kernel 加速。

## C550 架构与 profiling 支持的优化

本节用三类证据解释优化：实际执行二进制中的 LLVM 用于确认访存、数据布局和同步结构；设备活动时间线用于统计 kernel 与设备复制的持续时间；完整 Host API 计时用于判断调用方的收益。三者分别记录，event 跨度不能当作纯 kernel 时间。除注明的历史原生配对统计外，下列数字均为各项独立实验中控制实现与候选实现的同轮对照，单位为 μs；最终版本相对 mcRAND 的结果统一见验收第一节。

本次 C550 编译目标报告的 warp 宽度为 64，因此 raw 递推使用的 4 warps 对应 256 threads，成对递推的 2 warps 对应 128 threads。这是已验证的线程映射，没有单独测得其加速比。

**1. 用共享内存复用多轮递推的状态。**

MTGP32 在多轮递推中反复读取同一组状态。实际 LLVM 确认，TLE `local_ptr` 可将每个 CTA 的 4 KiB 状态保留在共享内存中，循环内相应的 global 访问改为 shared 访问，同时保持 192 个状态和每步 256 words 的输出顺序。16M uniform FP64 的 kernel 时间从 569.088 降至 483.584，完整 API 从 574.878 降至 486.818。

Poisson 进一步将长度不超过 1024 的 alias 表放入共享内存。λ=1000、16M 时，kernel 从 760.064 降至 455.424，代价是最多额外 8 KiB shared。两项实现都保留数据依赖所需的同步，不能仅按 barrier 数量解释收益。

**2. 拆开 XORWOW 的整数生成与 FP64 变换。**

融合版本将浮点变换限制在 256 个程序中。两阶段实现保持 raw 顺序，将变换展开为 65536 个程序：16M normal 的设备时间从 1254.144 降至两阶段合计 788.992，完整 API 约从 1257 降至 792；lognormal 的设备时间从 2035.712 降至 1170.944。

这项收益以 128 MiB raw 暂存和约 256 MiB 额外读写为代价，enqueue 也约从 20 增至 40。Trace 确认了设备端收益，但实验没有分别隔离程序数和寄存器变化的贡献。

**3. 删除 FP64 exp 在已知范围内不需要的处理。**

在已证明的输入范围内，lognormal 可省去部分通用范围处理。有限范围路径保留 degree-13 系数、Horner 运算顺序与精度要求；LLVM 中的 SSA 赋值由 203 减至 167，二进制资源记录中的寄存器由 108 减至 96。16M transform kernel 从 1022.464 降至 966.400，完整 API 从 1363.227 降至 1308.213。

FMA 依赖深度仍为 29，因此这里的收益来自删除多余处理，没有证据表明主数学依赖链变短。范围外的参数继续使用通用实现。

**4. 复用有界窗口内的转换结果，减少短调用的重复提交。**

cProfile 指向逐次转换启动、视图构造和复制分发。实现沿用有界 raw 窗口，缓存转换后的值，再通过当前 stream 的 MACA D2D 复制写入用户输出；应用范围为 N≤65536。计时包含全部 refill、转换重建和复制，未只测缓存命中。

raw32 也采用这一窗口：refill 时融合写出本次输出，缓存命中时通过当前 stream 的 D2D 复制输出。对 N=17、256、1024、16385、65536 的两种执行顺序，完整 API 时间几何平均从 16.3069 降至 7.18765，约 2.26874×。N=17 在两种执行顺序下的时间为 15.062→6.567、14.830→6.547；N=65536 为 17.181→9.873、17.113→9.901。设备活动却分别从 1.952 增至 3.404、从 3.844 增至 8.930，因此这里改善的是提交路径。N=65537 保持原路径，其控制/候选几何平均为 0.97690，边界负结果保留。

该 raw 候选的 62 条正确性记录、938 项布尔比较和 116 次独立状态及缓存参考全部通过，包括六个物理递推位置不同的 fresh aligned 对照。raw32 不新增派生数组，但将短对齐输入纳入预取后，会使用原有上限约 4 MiB 的 raw 窗口；该存储与下述派生数组容量分别计算。

同一份 raw32 实现的两次正式运行也保留了不同的原生时间：GPU5 的 44 点 FlagRAND/mcRAND 时间几何平均为 10.0849/12.5913，GPU3 为 10.0550/19.1975，对应加速比为 1.2485× 和 1.9093×。FlagRAND 时间接近，而 mcRAND 时间变化较大；这些是不同设备、不同轮次的观察。改动收益采用前面的同轮控制实验判断，跨轮比值的差异结合两侧绝对时间解释。

uniform 与 Poisson 的独立实验分别按先控制后候选、先候选后控制的顺序运行；设备活动为 kernel 与 gpu_memcpy 持续时间之和。

| 配置 | 第一顺序完整 API | 反向顺序完整 API | 设备活动：控制→候选 |
|---|---:|---:|---:|
| uniform FP64，N=17 | 15.352→8.477 | 14.953→8.623 | 2.336→3.572 |
| uniform FP32，N=17 | 14.886→7.567 | 14.881→7.587 | 1.944→3.690 |
| Poisson，λ=1000、N=17 | 19.266→11.036 | 19.267→10.924 | 2.230→3.574 |

这些配置的设备活动增加，完整 API 却变快，收益主要来自更短的主机提交路径。Poisson 在 128 次调用中的转换由 128 次减至 3 次，同时增加 128 次 D2D。N=65536 时，正序 API 为 22.447→15.404，设备活动却从 6.474 增至 13.172，复制成本已开始限制收益。N=65537 仍执行原路径；两个 λ、两种执行顺序的控制/候选仅为 0.9500–0.9670。两臂 trace 结构相同，实验 wrapper 增加了主机分派，其全部成本未单独隔离；这些负结果完整保留。

normal/lognormal 也存在同源的逐次转换开销。较早的 fresh-clone 测试中，lognormal FP64 全 42 点 GM 为 0.873118；33 个短输入的 FlagRAND 与 mcRAND 时间几何平均为 18.482 和 15.535，9 个大输入的 FlagRAND 时间与前轮接近。后续在同一张 GPU5 上，对 N=18、128、65536 分别进行两种执行顺序的独立对照：

| API | 目标点完整 API 时间几何平均：控制→候选 |
|---|---:|
| normal FP32 | 16.676→9.904 |
| normal FP64 | 17.434→12.357 |
| lognormal FP32 | 16.642→10.081 |
| lognormal FP64 | 19.979→13.278 |

四个 API 共用一个最近结果数组，缓存身份包含 raw 窗口、分布、精度、参数位模式和 raw 起点余数，切换时替换该数组。218 条正确性记录中的 3546 项布尔比较、368 次独立 raw 状态与缓存参考全部通过。其正负结果仍需分别解释：N=65536 的 normal FP64 正序 API 从 18.941 增至 20.181，设备活动从 17.884 增至 18.344，其中候选 D2D 为 13.020，复制成本抵消了主机收益；normal FP32 在同一 N 的设备活动从 5.200 增至 10.014，API 却从 19.129 降至 11.172，主要改善了提交路径。N=65537 边界控制和所有慢点均保留，没有按单点结果临时调整阈值。

缓存容量也计入实现取舍。uniform 两精度与 Poisson 三类派生数组的历史上界是 `16×(1048576+255)` 字节，约 16 MiB。加入四个 normal/lognormal API 共用的单个数组后，**当前缓存条目保留的派生数组总上界为 `20×(1048576+255)=20976620` 字节，约 20 MiB**；其中 normal/lognormal 合计新增不超过约 4 MiB，并非每个 API 各存一份。raw、alias 表以及尚未完成的 stream 暂时持有的旧存储另计。

Poisson 只保留最后一个表身份（threshold/aliases 对象及 first/size）对应的两个 offset parity，不按 λ 累积缓存。各类派生引用随耗尽、raw 替换和 reset 清理，已排队的复制遵循 stream 生命周期。参数或模式变化会重新转换窗口；固定参数性能测试包含窗口耗尽后的重建，但不代表频繁切换参数的工作负载。上述候选倍率不等同于原生验收加速比。

**5. 保留寄存器减少却变慢的反例。**

将 XORWOW 循环展开从 4 改为 1 后，寄存器由 174 降至 96，两臂 spill 均为 0；但 16M normal kernel 从 1254.144 增至 1342.464，约慢 7%，因此保留原展开方式。这个对照说明，寄存器数量需要结合实际设备时间解释，不能直接当作 occupancy 或性能改善的证据；它也不足以确定变慢来自哪一种指令调度机制。

**6. 共享参数表有小幅收益，仍保留为实验。**

将两张 16 项 GF(2) 表放入 shared，可用查表替代部分条件选择与 XOR。MCPTI 的前后差分显示，`inst_executed` 减少 11.08%，`shared_load` 增加 49.96%，寄存器由 37 降至 28；但 raw 16M 完整 API 在两种执行顺序下只改善 1.31%–1.48%。

这项实验明确呈现了指令减少与共享访存增加之间的取舍：额外使用 128 字节 shared，并增加 shared load。由于完整 API 收益有限，没有将它接入生产，也没有据此扩大分派范围。

上述受控实验用于解释优化机制。最终版本相对 mcRAND 的完整结果、设备和覆盖范围见第一节，正确性执行次数见第二节；各阶段原始结果保留在迭代记录中。

现有证据支持 64-lane 线程映射、共享内存复用、两阶段变换、等价运算精简及主机提交路径优化。LLVM 提供静态结构信息，资源记录给出寄存器和共享内存用量，trace 与已校准的 MCPTI 事件提供实际执行证据；目前尚未取得发射配对、动态 stall 或可信目标 ISA 反汇编。因此不将这些收益归因于双发射，也不宣称已测得实际 occupancy 提升。
